# Online listing continuity

The user requests a market/product review, an executable next-stage goal and autonomous implementation. Reuse the current isolated developer checkout. The implementation choice is a small reliability stage before more issuer exceptions; this is the agent's decision under that authorization.

## Intent and approaches

The existing online workflow loses its shared listing prerequisite during temporary source failures. Retry-only retains the interruption; a disk cache adds rights, storage and migration scope. Use a session-only last-good classification instead, preserving the existing four-source identity and financial gates. No automatic network retries are added: access limits and repeated clicks must not be disguised as recovery.

On an explicit peer refresh, attempt classification once. If the source is unavailable and this same session holds a complete validated classification whose four original observations are no more than 24 hours old, continue with that classification and clearly disclose the failure and dated reuse. Never renew source timestamps. A malformed successful packet is not a recoverable access failure. Recheck ticker/CIK and all issuer, annual, currency, price and peer conditions independently. A failed financial update replaces the prior verdict. Ordinary renders remain network-free.

## Boundaries

- No new dependencies, credentials, disk source cache, source approval, canonical writes or readiness updates.
- Preserve the directory creation age rule of seven days independently from the 24-hour observation limit; future dates are invalid.
- Retain per-source safe attempt status, URL, timestamp, byte count and raw digest when available. No response bodies, exception messages, cookies or headers in diagnostics.
- Keep directory-empty, transport, redirect/schema and source-date failures distinct. No empty directory admission or SEC-only substitute.
- Workbench and Discover use the same fresh-classification validator; preserve Discover's bounded session sampling and denominator behavior.
- Strengthen identifier/startDate/endDate leaf validation before extending exact-source contracts; do not broaden numeric parsing.
- Show attempt time and original listing observation/creation dates separately in valuation and sources. Dated reuse is visible before and after action.
- Preserve all current financial methods and minimum-three reference rule. Market-wide coverage, ADS/FX, successor annual basis, economic-peer review, commercial rights and hosted operations remain separately gated.

## Acceptance

Synthetic negative cases prove primitive rejection, incomplete-source rejection, safe diagnostics, expiry/future/tamper/mode/CIK withdrawal and unchanged source dates. A source failure with a recent session receipt permits fresh financial collection, never old financial verdict reuse. Live success replaces the session receipt; no prior receipt means held. Desktop and phone checks show returned/reused/held states and source details. Exact-head full tests, independent review, protected-file hashes and a private evidence packet precede developer-branch synchronization.
